# VEIL 개발 현황과 인수인계

기준일: 2026-11-22. 이 문서는 팀원이 처음 저장소를 받았을 때 현재 코드를 이해하고 후속 개발을 시작하기 위한 설명입니다. 기능 구현과 실제 운영 검증을 구분합니다.

## 지금 어디까지 구현했나

| 영역 | 현재 구현 | 검증·한계 |
|---|---|---|
| 실행·화면 | Python + Flask, 연구자·관리자 로그인, 연구 노트와 검사 데스크, 모바일 배치, 투명 VEIL 로고 | 로컬 브라우저 확인. 외부 서비스 배포는 하지 않음 |
| 분석 | 현재 입력과 같은 노트의 이전 최대 4개 입력 검사, SAFE / CAUTION / BLOCKED 분류 | 키워드·패턴 기반 임시 점수. 정밀 NLP 모델 없음 |
| 변환 | 마스킹·인물 가명화, 변환 전후 비교, 승인 후 재검사, 응답의 가명 복원 | 이름 등 탐지 규칙 범위가 제한적. 마스킹 정보는 복원하지 않음 |
| 전송 통제 | 최신 입력·정책·분석 결과 확인, BLOCKED 전송 금지, CAUTION 사유 확인 | UI 버튼과 별개로 서버에서도 검증 |
| 실제 AI 어댑터 | OpenAI Responses API, 관리자 키 등록, 인증·한도·시간 초과 오류 처리 | **실제 키로 전송·응답 수신은 아직 미검증**. 테스트는 네트워크를 대체함 |
| 계정·정책·로그 | SQLite 개발용 계정, 로그인 실패 잠금, 정책 버전, 최소화 로그, 보관 기간 | 중앙 보안 서버·정책 캐시는 아직 없음 |
| 테스트 | 업무 로직 19 + Flask 14 + OpenAI 10 = 43개 | 합격은 테스트 범위에 대한 결과이며 실제 API·탐지 정확도 보장은 아님 |

## 먼저 실행하고 확인하기

설치 명령과 계정은 [README](../README.md)를 따릅니다. Python 실행 시 `-X utf8`을 붙이면 한글 경로에서 인코딩 문제를 줄일 수 있습니다.

1. 연구자로 로그인하고 첫 화면과 예시 세 가지를 확인합니다.
2. **개인정보가 담긴 연구 계획** → **검사하고 보내기** → 주의 경고 → **변환 미리보기**를 확인합니다. 이 단계까지는 API 키가 필요 없습니다.
3. **승인하지 않고 돌아가기**로 원문이 유지되는지 확인합니다.
4. **새 노트** → **고민감 정보 검사** → 검사. 그대로 전송하는 버튼이 없는지 확인합니다.
5. 관리자 계정으로 정책과 보안 기록을 확인합니다. 키 등록·정책 저장은 같은 PC의 현재 Flask 서버에 적용됩니다.
6. 유효한 API 키를 등록한 후, 민감정보 없는 공개 질문으로 실제 응답을 검증합니다. 키 미등록 오류를 실제 AI 응답으로 혼동하지 않습니다.

각 예시는 새 노트에서 시작해야 독립적으로 비교할 수 있습니다. 이전 위험 입력이 같은 노트에 남아 있으면 다음 질문에서도 경고가 나타날 수 있습니다.

## 한 요청이 지나가는 코드

1. `static/app.js`의 `analyze()`가 `/api/analyze`에 현재 입력을 보냅니다.
2. `web.py`가 로그인·역할·CSRF를 확인하고 `PCAgent.analyze()`를 호출합니다.
3. `analysis.py`가 정책과 대화를 검사하고 등급·탐지 정보를 반환합니다.
4. `renderPanel()`이 등급에 맞게 화면을 전환합니다. SAFE면 전송, CAUTION이면 변환 또는 사유 확인, BLOCKED면 변환·수정·취소만 가능합니다.
5. 변환은 `/api/preview` → `/api/approve`를 거칩니다. 서버가 보관한 미리보기만 승인할 수 있고 승인 후 다시 검사합니다.
6. `/api/send` → `PCAgent.send()` → `TransmissionGuard.send()`가 최신 검사·정책·사유를 다시 확인합니다.
7. `OpenAIClient.request()`가 승인된 현재 입력만 보냅니다. 원문 대응표와 이전 대화는 API에 보내지 않습니다.
8. 응답 수신 후 메모리의 가명표로 응답을 복원해 표시하고, DB에는 최소화된 처리 기록을 남깁니다.

## 유지해야 할 조건

- 프롬프트나 정책이 바뀌면 이전 검사·미리보기로 전송하지 않습니다.
- CAUTION의 사유 원문은 DB에 저장하지 않습니다. BLOCKED는 사유를 적어도 직접 전송할 수 없습니다.
- 브라우저에 API 키를 반환하거나 키·원문·가명표를 진단 로그에 추가하지 않습니다.
- 응답을 잃었으면 이미 처리됐을 가능성이 있으므로 무조건 재전송하지 않습니다. 현재 `SEND_UNKNOWN`은 새 노트에서 사용자가 다시 시작하도록 합니다.
- 서버가 PC에서 실행되는 현재 구조와 중앙 서버 구조를 혼동하지 않습니다. 이 앱을 그대로 외부에 공개하지 않습니다.
- 기존 테스트를 통과한 뒤 실제 API 결과·추가 한계를 문서에 업데이트합니다.

공유 락, 단일 프로세스 메모리, 전송 성공 이후 로그 실패 시 복구 등은 기초 구현의 제한입니다. 이 경계를 바꿀 때는 담당자 간 계약부터 맞춥니다.
