# VEIL 4인 개발 역할 분담안

팀원 이름·숙련도·제출일은 아직 확인되지 않아 A~D로 배정합니다. **A는 본인**, B~D는 팀 협의로 정하면 됩니다. 역할은 제안이며 팀원에게 전달하거나 확정하지 않았습니다.

현재 기초 구현에는 `openai_client.py`의 실제 OpenAI Responses 연결, 관리자 키 등록, 응답 불명 처리와 VEIL 원본 로고가 포함됩니다. C는 이 코드를 이어받아 유효한 키로 실호출 검증 후 비동기 작업·취소·스트리밍을 확장합니다. A는 연구자 UI와 전체 흐름, B는 분석·변환 정확도, D는 관리자·계정·정책·로그를 맡는 분담을 유지합니다.

## 담당 경계

| 담당 | 책임 | 주요 코드 | UC/GUI | 이번 단계 다음 산출물 |
|---|---|---|---|---|
| A · 본인 | Flask 웹 GUI·전체 흐름·통합 | `templates/workspace.html`, `static/app.js`, `static/app.css`, `web.py`, `controller.py` | UC-01~05 연결, G01~G16 | 연구자 UI 개선, Flask API 연결, 전체 시연 |
| B | 로컬 보안 분석·변환 | `analysis.py`, `domain.py` 중 탐지/대화/가명 | UC-03/05 | 탐지 사례집, 탐지·오탐 평가, 문맥 모델 어댑터, 변환 전략 |
| C | AI 연동·전송 통제·장애 처리 | `gateway.py`, `openai_client.py` | UC-02/04 공통 전송, G11/G15 연계 | 실제 계정 검증, 비동기 작업·취소·스트리밍, 중복 전송 방지 |
| D | 서버·계정·DB·정책·로그와 관리자 화면 | `storage.py`, `templates/admin.html`, `web.py` 관리자 API | UC-01 서버, UC-06~08, A01~A04 | 중앙 서버 API, 3NF 테이블, 정책 버전, 기록 조회·자동 파기 |

본인은 먼저 모든 모듈의 **호출 흐름을 이해하고 GUI를 완성**합니다. 분석 모델·AI 공급자·서버까지 혼자 완성하려고 범위를 늘리지 않습니다. 이번 기초 구현은 팀이 같은 실행 기준을 공유하기 위한 출발점이고, 팀원별 후속 기능의 완료를 의미하지 않습니다.

## 충돌 없이 같이 개발하는 방법

1. 저장소는 `veil/` 폴더 자체를 루트로 사용합니다. 설치·브랜치·PR 절차는 [협업 방법](../CONTRIBUTING.md)을 따릅니다. 팀원은 비공개 저장소 초대를 수락한 뒤 clone합니다.
2. 브랜치는 `feature/agent-ui`, `feature/local-analysis`, `feature/ai-gateway`, `feature/security-server`로 나눕니다.
3. 관리자 HTML은 이미 `templates/admin.html`로 분리했습니다. A는 `static/app.js`를 연구자/관리자 스크립트로 분리해 D에게 넘깁니다. 공용 CSS와 `web.py`는 동시에 덮어쓰지 않도록 PR에서 조정합니다.
4. `domain.py`와 `controller.py`의 함수 인자·반환형을 바꿀 때는 영향을 받는 담당자와 먼저 합의합니다. A가 통합 변경을 반영합니다.
5. 각 담당자는 본인 기능 테스트와 시연 방법을 작성합니다. PR은 최소 한 명이 검토하고, 자동 테스트와 GUI 시연을 통과한 뒤 합칩니다.
6. 검사·변환·가명 복원은 PC에서 처리하고 승인된 현재 입력만 OpenAI로 보냅니다. 탐지 원문/가명표를 외부 보안 서버 API·진단 로그에 추가하지 않습니다.

## 지금 합의할 모듈 계약

| 호출 | 입력 → 출력 | 반드시 지킬 조건 |
|---|---|---|
| `SecurityAnalyzer.analyze` | Prompt, Policy, Conversation → AnalysisResult | 본문 revision·정책 version 일치, 핵심 키워드 즉시 BLOCKED |
| `PromptSanitizer.preview` | Prompt, Policy, Conversation → ConversionPreview | 원본/현재 본문 변경 없음, 현재 입력만 치환 |
| `PCAgent.approve` | Preview → AnalysisResult | 오래된 미리보기 거부, 승인 후 재검사 |
| `TransmissionGuard.send` | Prompt, Policy, Gateway, reason → 응답 | 최신 검사·사유 검증, BLOCKED/미검사 전송 금지 |
| `AIProviderClient.request` | 허용된 본문 → 응답 또는 오류 | 원문 로그 금지, 실제 연동 시 timeout·멱등 키 확장 |
| Repository | 계정·정책·최소화한 로그 | UI 권한 검증과 별개로 서버에서도 인증·인가 |

브라우저는 fetch로 요청하고 처리 중 로딩 화면·입력 잠금을 적용합니다. Python 함수는 동기식이며 로컬 공유 저장소는 락으로 직렬화됩니다. C가 실제 네트워크 작업을 추가할 때 A와 함께 worker/queue와 작업 ID를 도입합니다. 실행 중 입력 변경·로그아웃·정책 갱신 시 오래된 결과를 폐기해야 합니다.

## 단계별 통합 계획

기간은 제출일을 알기 전의 상대 순서입니다. 날짜를 확정한 일정이 아닙니다.

| 단계 | A · 본인 | B | C | D | 완료 기준 |
|---|---|---|---|---|---|
| 1 · 기초 확인 | 실행·시연, 코드 흐름 이해 | 탐지 규칙/데이터셋 검토 | 전송 불변 규칙 검토 | DB/정책 요구 대조 | 네 명 모두 같은 데모 실행 |
| 2 · 각자 구현 | 관리자 JS 분리, UI 개선, Flask 연결 정리 | 탐지/마스킹 전략, 사례 테스트 | 공급자 1개·오류 분류·모의 테스트 | 중앙 서버 인증·정책·기록 API | 모의 객체로 각 모듈 독립 테스트 |
| 3 · 연결 | 비동기 제어·관찰자·전체 통합 | 누적 문맥 분석, 제한시간 | 실제 timeout, 재시도·멱등성 | 정책 캐시 지원, 로그 파기 작업 | 성공/실패/정책 변경 통합 시나리오 |
| 4 · 발표 준비 | 시연 동선·설치 안내 | 정확도/성능 측정 | 호출 실패 재현 | 로그 원문 미저장 검증 | 요구사항 추적표·시험 결과 갱신 |

## 공동 완료 기준

- 공개 자료는 검사 후 전송, CAUTION은 사유 없이 불가, BLOCKED는 어떤 버튼 경로로도 전송 불가.
- 변환 거부는 원문 유지, 변환 승인은 재검사, 이전 대화 위험은 숨기지 않음.
- 입력·정책·대화가 바뀌면 이전 분석/미리보기를 재사용하지 않음.
- AI 실패 시 성공 로그를 만들지 않고 입력을 유지. 실서비스 응답 불명은 무조건 실패로 간주하지 말고 별도 처리.
- DB/외부 보안 서버 API/로그 파일에 원문·변환문·가명표·비밀번호 평문 없음. PC 내부 localhost API는 입력 처리에 필요한 본문을 메모리에서 전달합니다.
- 관리자 메뉴 숨김만으로 끝내지 않고 서버에서 역할 권한 검사.
- FAST 1초 / PRECISE 3초 / 응답 10초 / 캐시 24시간은 설계 목표다. 실제 측정 없이 달성했다고 쓰지 않음.

## 수업 발표에서 본인이 설명할 부분

“저는 PC 에이전트의 GUI와 전체 유즈케이스 연결을 담당했습니다. 연구 노트 아래의 검사 데스크에서 경고와 변환문을 검토하고, 전송 통제를 거쳐 OpenAI Responses API를 호출하도록 구현했습니다. 요청 계약과 실패 처리는 테스트했으며, 실제 계정으로의 응답 검증은 API 키 등록 후 진행합니다. 정밀 분석 모델과 중앙 서버는 담당별로 확장합니다.”

위 문구는 직접 코드를 이해하고 수정·검증한 범위에 맞게 고쳐 사용합니다. 이번 생성 코드만으로 모든 기능을 직접 완성했다고 표현하지 않습니다.
